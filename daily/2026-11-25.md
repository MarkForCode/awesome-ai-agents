# 2026-11-25 幫 Agent 收拾善後：刪死碼、掃弱點、只讀查資料

> 今天收錄 4 個專案。程式 Agent 寫得快，留下的死碼和不安全的設定也多，shrink-anything 和 safe-anything 分別處理這兩件事，而且都用測試或規則把關，不靠 Agent 自己說了算。另外有一個只能讀不能寫的 SAP MCP 伺服器，以及一個要求 Agent 拿出證據的研究 Skill。

## 今日新收錄

- **[EL4CTEO/shrink-anything](https://github.com/EL4CTEO/shrink-anything)** · 程式開發 Agent
  一般死碼工具只會列清單，它會直接刪，但每刪一批就跑你指定的測試指令，必須通過而且跑到的測試數量不能變少才保留，失敗就拆開找出是哪一刀出問題再放回去。判斷方式是數名稱出現的次數，不建呼叫圖，所以只會漏抓、不會誤判；公開 API、框架自動載入的檔案這類沒把握的部分，才交給 Agent 處理。提供 CLI、MCP 伺服器和 Claude Code 外掛。
- **[erkamyaman/safe-anything](https://github.com/erkamyaman/safe-anything)** · 程式開發 Agent
  一般的弱點掃描器管程式碼和相依套件，這個工具多了一類「Agent 設定」：例如開了 `--dangerously-skip-permissions`、預先允許 Bash、用沒鎖版本的 `npx` 跑 MCP 伺服器，或 Skill 裡藏著 `curl | sh` 和讀取 `~/.ssh` 的指令。不用設定也不用帳號，發現高風險問題會回傳非零值，可以直接放進 pre-commit 或 CI。它本身也是 MCP 伺服器，可以讓 Agent 安裝別人的 Skill 之前先掃一遍。
- **[w1ccc/sap-data-mcp](https://github.com/w1ccc/sap-data-mcp)** · MCP 伺服器與 SDK
  企業最擔心的是 AI 接上 ERP 後亂改資料。這個專案把唯讀寫死在程式碼裡：RFC 只能呼叫 98 個標準讀取函式，HTTP 只發固定的 GET，Tool 不接受任意 URL 或原始查詢，密碼只放在本機 `.env`。三個服務共 400 多個 Tool，涵蓋採購、銷售、庫存、財務等模組，問「這張 PO 為什麼還沒付款」就能自己查訂單、發票和未清項。非 SAP 官方產品。
- **[AyushRajSinghParihar/weaponized-curiosity](https://github.com/AyushRajSinghParihar/weaponized-curiosity)** · 研究與通用 Agent
  讓 Agent 做研究時，常見的問題是查到第一個看起來合理的答案就停。這個 Skill 要求 Agent 先找最可能改變結論的證據，結論接近時要說出「什麼情況會翻盤、最便宜的驗證方法」。自動實驗模式可以設定目標和實驗次數上限，在隔離的副本裡改程式並用固定的評測比較，適合調效能這類能量化的工作。
