# 2026-11-20 Agent 寫完之後：審查、測試與省錢

> 今天收錄 5 個專案，大多處理 Agent「做完事之後」的問題：怎麼審查它寫的程式碼、怎麼確認它真的做了它說的事，以及怎麼少花一點 token。另外還有一個把韌體分析交給 Agent 的 MCP 伺服器，和一個從手機管理多台機器上程式 Agent 的自架介面。

## 今日新收錄

- **[bashovski/reflektor](https://github.com/bashovski/reflektor)** · 程式開發 Agent
  Agent 一次改幾十個檔案時，直接讀 diff 很累。Reflektor 把分支整理成瀏覽器裡的報告，有請求流程圖、資料庫變更、測試結果和 UI 截圖，你留的意見會交回給 Agent 處理，Agent 再修改、產生下一輪報告。在本機就能用，要分享給團隊才需要它的線上服務。
- **[srpadmanabhuni/agentest](https://github.com/srpadmanabhuni/agentest)** · Agent 開發框架
  多數 Agent 評測看的是最後回了什麼，agentest 看的是 OpenTelemetry trace 裡實際呼叫了哪些工具、順序對不對、最後留下什麼狀態，例如 Agent 說「已加入購物車」但購物車其實是空的。檢查是固定規則，不呼叫模型，結果可以重現，適合放進 CI。目前是個人維護、剛發布不久。
- **[prapaa-ai/agav](https://github.com/prapaa-ai/agav)** · 程式開發 Agent
  又一個終端機程式 Agent，不同的是它把重點放在「同樣的模型少花錢」：重用快取、偵測卡住的修復迴圈、限制重試。作者有公布跟 Codex 的成本比較，也老實寫出通過率比較低，數據和方法都放在網站上。仍是 Beta。
- **[JoeyZzZzZz/treasure-map](https://github.com/JoeyZzZzZz/treasure-map)** · MCP 伺服器與 SDK
  Agent 讀單一函式還行，面對整份韌體的上百個二進位檔就容易看幾個就收工。Treasure Map 先用 Ghidra 把高風險呼叫點、資料來源、誰寫入設定值都整理好，並記錄哪些還沒讀過，避免把「沒看」當成「沒問題」。它也能比對兩版韌體的修補內容，判斷交給模型和人。
- **[cloveric/tarobird](https://github.com/cloveric/tarobird)** · 無程式碼平台與自架介面
  不重寫 Agent，而是直接跑 Codex、Claude Code 等官方 CLI，把它們收進一個像通訊軟體的介面，桌面和手機同步。可以把不同機器上的 Bot 拉進同一個群組，互相交辦工作和檔案。採 AGPL-3.0 授權，多數引擎預設完整權限，使用前要先調整。
