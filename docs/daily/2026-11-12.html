2026-11-12 讓 Agent 在沙盒和手機上做事，人只在關鍵時刻出手

這幾天新冒出來的專案有個共同點：不再只追求 Agent 能做多少事，而是設計好「哪裡讓它放手、哪裡要人確認」。今天收錄 4 個，兩個是隔離環境，一個管理背景任務，一個讓 Agent 操作手機。

今日新收錄

  • KKKKhazix/agent-autoloop · 程式開發 Agent
    用一份 rules.json 設定什麼事件交給哪個命令列 Agent、在哪個目錄做，例如每天早上寫早報、有新 issue 就處理。Agent 遇到刪資料、花錢這類拿不準的事會退出並推卡片給你，等你回覆期間不占程序也不花 token。跟 Orca 這類同時指揮多個 Agent 的工具不同，它的重點是無人值守。
  • devvmhq/devvm · 程式開發 Agent
    在專案資料夾執行 devvm，就會開一台只掛載該資料夾的虛擬機，工具鏈自動偵測，GitHub、Claude Code 的 token 留在本機。也能用 --clone 讓 Agent 在自己的副本工作，之後再 fetch 回來審查。比起 Docker 容器，隔離更徹底，適合想開放較多權限給 Agent 的情境。
  • DIYgod/pinky · 瀏覽器與電腦操作
    透過 MCP 讓 Claude Code、Codex、Cursor 操作真的手機，Android 和 iPhone 都支援。付款、轉帳預設要你按允許，銀行與密碼管理 App 預設對 Agent 隱藏，而且這些規則由 Pinky 的閘道執行，不是靠提示詞要求 Agent 自律。目前仍是 pre-alpha。
  • shanselman/sandbox-mcp · MCP 伺服器與 SDK
    利用 Windows 內建的 Windows Sandbox，讓 Agent 在全新的 Windows 11 裡安裝、點擊、測試你的桌面程式，抓出「在我電腦上可以跑」的相依問題，最後連機器一起丟掉。CLI 可以單獨使用，MCP 介面是選配。需要 Windows Pro 以上版本。

讀者投稿

  • vostride/agent-qa · 瀏覽器與電腦操作
    由專案維護者投稿。用自然語言描述使用流程，Agent 會在網頁、Android 或 iOS 上實際操作測試，失敗時把出錯的步驟和截圖放在一起，學到的經驗存成 repo 裡可審查的檔案。注意它採用 FSL-1.1-ALv2 授權：原始碼公開，但兩年內限制競爭用途，不屬於 OSI 認可的開源授權。
